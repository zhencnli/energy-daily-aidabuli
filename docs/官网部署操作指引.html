官网部署操作指引

「AI答不锂」官网改版已完成并推送到 GitHub，但新官网还没上线。 原因：上传官网文件（index.html / logo.jpg）需要写入 COS 桶根目录， 而你的 COS 子账号策略只放行了 energy-daily/* 前缀，导致部署被拒（AccessDenied）。

你只需要做 2 步： ① 在腾讯云 CAM 把更新后的策略重新应用到子账号（放开桶根写入）； ② 在 GitHub Actions 手动跑一次 Deploy site。 做完后新官网上线，其余全自动由云端完成。

总览：为什么必须你来做

第 ① 步是安全策略变更，只能由你在腾讯云控制台操作，我无法代做；第 ② 步是云端部署触发器。

第 ① 步 · 腾讯云 CAM 重新应用策略

目标：让 COS 子账号（密钥 SecretId 以 AKID******… 开头，即我们新建的专用子账号）拥有桶根 index.html / logo.jpg 的写入权限。

1

打开访问管理 CAM

浏览器访问 console.cloud.tencent.com/cam/overview ，左侧菜单进入「用户 → 用户列表」。

找到密钥以 AKID****** 开头的子账号 → 点进去 →「权限」Tab。
2

把策略更新为最新版本（关键）

在策略编辑框里，把 PutObject 那段 resource 数组整体替换为下面这份（或直接把仓库里 docs/cos-cam-policy.json 的内容整段粘贴）。重点是新增的两条桶根资源：

"qcs::cos:ap-shanghai:uid/1500638180:aili-1500638180/index.html",
"qcs::cos:ap-shanghai:uid/1500638180:aili-1500638180/logo.jpg"
绿色高亮的两行就是「放开桶根写入」的本质。保存后权限即时生效。
如果之前是「按策略语法创建」的自定义策略，也可在 CAM「策略 → 自定义策略」里找到它直接编辑；或在「用户 → 权限」里新建并关联一份新策略、再解除旧策略。

第 ② 步 · GitHub Actions 手动运行 Deploy site

策略生效后，触发部署。因为这次改动没动 site/ 目录，site.yml 不会自动跑，需要你手动触发一次。

1

打开仓库的 Actions 页

访问 github.com/zhencnli/energy-daily-aidabuli/actions ，左侧工作流列表选中 Deploy site。

左侧选 Deploy site → 右侧点「Run workflow」，确认分支是 main，再点一次 Run workflow。
2

等待变绿并验证

约 30–60 秒后出现绿色 ✓ 即成功。验证：

看运行日志最后一行Last-Modified 时间变新页面含「AI答不锂」+ 邮箱

成功后官网文件已写入桶根。可用 curl -I https://aili-1500638180.cos-website.ap-shanghai.myqcloud.com/ 看 Last-Modified 是否为今天。

已知问题 · 浏览器会「下载」而非「渲染」官网

2024 年后建的 COS 桶，用默认 / 静态网站域名访问任何对象都会被腾讯云强制追加 Content-Disposition: attachment，所以浏览器打开官网会下载 index.html 而不是显示页面。 这是腾讯云策略，与本次部署无关。

根治方案（单独任务，未做）：按 docs/Apple Podcasts 提交清单.md 配置 Cloudflare 边缘代理， 再把 config.cos.public_base 设为该代理地址，feed 内链接会自动改写。 在此之前，官网虽已上线，但建议用「查看源代码 / 下载后打开」或经代理访问来查看。

兜底 · 如果还失败

  • 跑完 Deploy site 仍是红色 / AccessDenied：说明第 ① 步策略没保存成功或绑错了子账号。回到 CAM 确认绑定到 AKID****** 子账号的那条策略确实含桶根两行。
  • 策略已对但仍失败：在 GitHub Actions 的 Secrets 确认 TENCENT_COS_SECRET_ID/KEY 填的是子账号密钥（主账号密钥已禁用）。
  • 不确定改对了没：把 CAM 里该策略的 JSON 贴给我，我帮你核对。
