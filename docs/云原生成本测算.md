## 三、三条实现路径对比（改造量差异极大）

| 路径 | 现金成本 | 单次时长限制 | 改造量 | 定时精度 | 综合评价 |
| --- | --- | --- | --- | --- | --- |
| **A. GitHub Actions** | **¥0**（私有仓 2,000 分钟/月免费，本项目约 300 分钟） | Job 最长 6 小时 | 小：现有脚本基本可复用 | cron 有 5–30 分钟延迟 | **推荐首选** |
| **B. 腾讯云函数 SCF** | ≈ ¥0（免费额度内） | 单实例最长 **900 秒** ⚠️ | 中：需拆分为搜索/合成/上传多个函数，依赖打包为层 | 精准 | 与 COS 同地域内网免费，但超时风险高 |
| **C. 轻量云服务器 + cron** | ¥10–30/月（新用户首年常有特价） | 无限制 | **几乎为 0**：脚本原样搬上去 | 精准 | 最省心、最像本地，可 SSH 调试 |
| D. WorkBuddy 云上模式 | ¥0 现金（消耗平台额度） | 待验证 | 中 | 精准 | 需先验证云沙箱能否 `pip install edge-tts` 并访问外网 |

**我的建议**：起步走 **A（GitHub Actions）**，零现金成本且改造量小；若你对 GitHub 不熟，走 **C（轻量服务器）**，月付十几元换来"和现在完全一样"的体验与 100% 可控。

## 四、必须知道的三个改造难点（非金钱成本）

1. **云端没有 WebSearch 工具**——这是最大的改造点。现有 Step 1 依赖 WorkBuddy 的联网搜索；迁到云端后必须二选一：
   - 接入搜索 API（Tavily / 博查 / Serper 等，多数有免费额度）
   - 改为抓取固定信源 RSS（北极星电力网、PV InfoLink、储能与电力市场公众号/网站等），成本 0 且更可控，但覆盖面依赖源质量
2. **SCF 的 900 秒天花板**：LLM 调用 + edge-tts 合成 6 分钟音频 + 上传，整体常在 3–8 分钟，容易逼近上限。选路径 B 必须做函数拆分或改用长时运行形态。
3. **edge-tts 是非官方接口**：微软未公开授权，长期商用存在被限流或变更的风险。建议生产环境切腾讯云 TTS（月增约 ¥1.4）。

## 五、迁移清单（若决定实施）

1. 选定路径（A/B/C）
2. 准备凭据：LLM API Key、搜索 API Key（或确定 RSS 源清单）、COS 密钥（已有，建议**轮换**——当前 SecretKey 曾在对话中明文出现过）
3. 改造脚本：TTS、RSS 生成、COS 上传三段可直接复用 `energy-daily/scripts/` 下现有文件
4. 密钥以环境变量/Secrets 注入，**不入库**
5. 配置定时：A 用 `cron: '0 23 * * *'`（UTC）= 北京时间 07:00；B 用 SCF 定时触发器同样按 UTC 换算
6. 加失败告警（邮件 / 企业微信机器人）
7. 保留日前幂等覆盖逻辑（现有 `episodes.json` 已实现）
8. 迁移后**先并行运行 3 天**，确认无遗漏再关闭本机定时任务

## 六、附：当前（本机方案）的隐性成本

不改也能用，但需承担：
- 电脑必须常开（已把休眠超时改为"从不"，睡眠本就为"从不"）
- 07:00 触发错过不会补跑
- 出差/断电/系统更新重启都会漏更

折算成"可靠性成本"，约等于每月数次人工补跑。是否值得花 ¥5–15/月 + 一次性改造换掉它，取决于你对断更的容忍度。
